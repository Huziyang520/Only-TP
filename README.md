# 🔒 Only TP

**English** | [中文](#中文)

A server-side command limiter for Minecraft: let your players use teleport commands only, or block every non-teleport command — without giving them operator rights.

---

## 📖 What it does

| Mode | Effect |
|---|---|
| **Allow TP only** | Regular players may use teleport commands. Everything else stays vanilla. |
| **Block non-TP** | Teleport commands are allowed for everyone; every other command is blocked. Operators can be given an extra command whitelist. |
| **Enable both** | Both rules apply at once, each with its own exemption list. |
| **Disable mod** | No restriction at all. |

- 🚫 Blocked commands answer with a red `Only TP: This command has been disabled!`
- 🎮 Blocked game-mode switching shows its own red notice.
- ⭐ Every mode has its **own exemption list** — players on it are never restricted.
- 🎯 Optional target selectors (`@a`, `@p`, …) for restricted players, switchable.

## 🚀 Installing

1. Put the jar into your **server's** `mods` folder (Forge, NeoForge or Fabric).
2. Start the server once. `config/onlytp-common.toml` and `config/onlytp-client.toml` are created automatically.
3. Edit the file, or use the in-game editor (below).
4. Pick a mode, fill in the exemption list and — if you want one — the operator command whitelist, then save.

> The mod is authoritative on the **server**. A client without it plays normally, it simply cannot open the editor.

## 🖱️ The in-game editor

Two independent entries:

- **Mod list** → *Only TP* → *Config*. Uses the loader's own configuration screen where one exists; otherwise it is generated by **Cloth Config API**, which is therefore needed on the client for that entry (1.20.x on every loader, 1.21+ on Fabric).
- **Pause menu** button — appears only with **AvalonBase** installed and opens AvalonBase's editor.

Editing requires operator permission on the server (the screen is read-only otherwise). If the server owner turns the entry off, the mod-list entry shows an "entry closed" notice and the pause button disappears.

## ⚙️ Configuration

Both files are plain TOML, safe to edit by hand at any time — changes apply **without restarting the server**.

`config/onlytp-common.toml` — the rules, decided on the server and sent to clients:

| Key | Meaning |
|---|---|
| `mode` | `disabled` / `allow_tp_only` / `block_non_tp` / `both` |
| `allow_entity_selectors` | Allow target selectors such as `@a` |
| `enable_config_entry` | Allow entering the visual editor (also shows the pause button when AvalonBase is present) |
| `mode_allow_tp_only` / `mode_block_non_tp` | Exemption lists of that mode |
| `command_whitelist` | Extra commands operators may use in "block non-TP" mode |

`config/onlytp-client.toml` — per-client preferences, never sent anywhere:

| Key | Meaning |
|---|---|
| `gui_button_style` | `0` = modern look, `1` = vanilla-style buttons |
| `enable_animations` | Interface open/close animations |
| `show_tips` | `1` = show the in-game tip about the editor |

## 💡 Good to know

- Which commands count as "teleport commands" is decided by the mod, not by the config.
- Command names are matched case-insensitively; a leading `/` is ignored.
- Everything is decided on the server: installing the mod on a client only adds the visual editor.

# 🔒 Only TP

一个 Minecraft 服务端的指令限制模组：让玩家只能使用传送类指令，或者禁止所有非传送指令 —— 不需要给他们管理员权限。

---

## 📖 它做什么

| 模式 | 效果 |
|---|---|
| **非OP玩家仅允许TP指令** | 普通玩家可以使用传送类指令，其它指令保持原版行为。 |
| **OP玩家禁止非TP指令** | 所有人都能用传送类指令；其它指令一律禁止。管理员可以额外配一份命令白名单。 |
| **同时启用** | 两套规则同时生效，各自带独立的豁免名单。 |
| **关闭模组功能** | 完全不做限制。 |

- 🚫 被拦截的指令会收到红字 `Only TP: 该指令已被禁止！`
- 🎮 被拦截的游戏模式切换会显示对应的提示。
- ⭐ 每个模式都有**自己的豁免名单**：名单里的玩家完全不受限制。
- 🎯 受控玩家是否可用 `@a`、`@p` 这类目标选择器，可单独开关。

## 🚀 安装

1. 把 jar 放进**服务端**的 `mods` 文件夹（Forge / NeoForge / Fabric）。
2. 启动一次服务端，会自动生成 `config/onlytp-common.toml` 与 `config/onlytp-client.toml`。
3. 直接改文件，或使用游戏内编辑界面（见下）。
4. 选好模式、填好豁免名单（需要的话再配管理员命令白名单），保存即可。

> 判定完全在**服务端**。客户端不装也能正常玩，只是打不开编辑界面。

## 🖱️ 游戏内编辑界面

两个互相独立的入口：

- **模组列表** → *Only TP* → *配置*。加载器自带配置界面时就用自带的；否则由 **Cloth Config API** 生成，所以该入口在客户端需要 Cloth（1.20.x 全加载器、1.21+ 的 Fabric 端）。
- **暂停菜单**按钮 —— 只在装了 **AvalonBase** 时出现，打开的是 AvalonBase 的编辑界面。

编辑需要在服务端拥有管理员权限（否则界面只读）。服主关闭入口后，模组列表入口只显示「入口已关闭」提示，暂停菜单按钮也不再出现。

## ⚙️ 配置文件

两个文件都是纯 TOML 文本，随时可以手改，**改动无需重启服务端**即可生效。

`config/onlytp-common.toml` —— 规则，由服务端判定并下发给客户端：

| 键 | 含义 |
|---|---|
| `mode` | `disabled` / `allow_tp_only` / `block_non_tp` / `both` |
| `allow_entity_selectors` | 是否允许 `@a` 这类目标选择器 |
| `enable_config_entry` | 是否允许进入可视化配置界面（装了 AvalonBase 时也决定暂停按钮） |
| `mode_allow_tp_only` / `mode_block_non_tp` | 对应模式的豁免玩家名单 |
| `command_whitelist` | 「禁止非TP指令」模式下管理员可额外使用的指令 |

`config/onlytp-client.toml` —— 只影响本机的偏好，不参与同步：

| 键 | 含义 |
|---|---|
| `gui_button_style` | `0` = 现代风格，`1` = 原版风格按钮 |
| `enable_animations` | 界面开/关动画 |
| `show_tips` | `1` = 进世界时提示一次编辑界面的用法 |

## 💡 使用须知

- 哪些指令算「传送类指令」由模组内置决定，不需要在配置里写。
- 指令名不区分大小写，开头的 `/` 会被忽略。
- 所有判定都在服务端完成；客户端装本模组只是为了拿到可视化编辑界面。
